# iced vs GPUI vs Rune: An Analyst's Take on NativeTube

NativeTube builds the same rich, media-heavy desktop client three times—in **iced 0.14**, **GPUI** (`gpui-pre` 0.3.12 + `gpui-component` 0.9.1), and **Rune** (`anomalyco/rune` rev `4fbd2d6`)—on one shared Rust core (`nt-core`) [docs/blog/coordinator-notes.md: 3 frontends]. Sharing the backend turns a usually vague toolkit debate into a controlled experiment in runtime efficiency, stability, and AI-agent buildability.

## 1. Verdict in 5 bullets

1. **For a media app, routing video around the UI framework matters more than which framework you pick.** Moving libmpv onto a desync Wayland subsurface below a transparent window cut playback CPU ~4.5× across all three apps—from 44–45% down to 9.0–10.0% [docs/media/README.md: 44–45%→9.0–10.0%]—and cut CPU instructions ~19× [docs/media/README.md: ~6,550M→328–353M].
2. **GPUI wins on rich UI velocity and agent ergonomics, at a steep tax in scrolling CPU, RAM, and binary size.** It needs ~28 h for YouTube UI parity versus ~44 h for iced and ~40 h for Rune [docs/review/youtube-parity.md: 28/44/40h], yet burns 3× Rune's CPU instructions while scrolling [docs/media/README.md: 3,020.93M vs 1,013.41M], ships the largest stripped binary at 52.7 MiB [docs/media/README.md: 52.7MiB], and carries a runtime re-entrancy panic Rust cannot catch at compile time [docs/upstream/gpui-reentrant-keystroke.md: entity_map.rs:192].
3. **iced is the leanest, fastest-starting, most predictable runtime—once rescued from its 0.14 defaults.** At NOW it leads on window map (190 ms), Home load (209 ms), open-to-frame (95 ms), warm switch (36 ms), idle/tour PSS (153/267 MiB), and binary size (29.6 MiB) [docs/media/README.md: NOW], with zero crashes in the 43-incident catalog [.cache/media/out/hiccups.json: 0 crashes]. The price is Elm-style overlay boilerplate and missing 0.14 basics (ellipsis, blur, `unfocus` helper, and a `HighPerformance` GPU default that woke the dGPU [docs/upstream/iced-power-preference.md: 339→199ms]).
4. **Rune's reactive `Live`/`Pixels` model posts the lowest scrolling and GPU-playback CPU numbers, but the toolkit is too immature for production.** It scrolls in 1,013.41M CPU instructions [docs/media/README.md: 1,013.41M] with ~2,500 initial lines of app code [apps/rune/NOTES.md: ~2,500], yet peaked highest in tour RAM (337 MiB [docs/media/README.md: 337MiB]), required `[patch.crates-io]` overrides [apps/rune/NOTES.md: winit+wgpu-hal], lacked a public raw Wayland display callback [apps/rune/NOTES.md: wl_proxy_get_display], and aborted in release builds on wrapped `LiveText` [docs/upstream/rune-wrapped-livetext.md: flatten.rs:259].
5. **Second-order platform traps rivalled renderer differences.** Default GPU/driver probing (`WGPU_POWER_PREF`, dual EGL vendors, CUDA probing), Cargo feature unification (`serde_json`'s `preserve_order` breaking GPUI's fixture replay [docs/blog/coordinator-notes.md: 1145 fixtures]), and an apparent CPU-vs-GPU inversion during scrolling [docs/media/README.md: wheel] shaped outcomes as much as UI architecture.

## 2. The evidence, by theme

### Speed
On NOW (AC, `balance_performance`, 3-run median), **iced** wins every latency metric: 190 ms window map, 209 ms Home, 95 ms open-to-frame, 36 ms warm switch [docs/media/README.md: 190/209/95/36ms]. **Rune** takes second on startup (238/252 ms) but trails on transitions (189 ms open-to-frame, 50 ms warm switch) [docs/media/README.md: 238/252/189/50ms]. **GPUI** launches slowest (293/310 ms) while beating Rune on transitions (118/43 ms) [docs/media/README.md: 293/310/118/43ms].

Bare shells show how misleading defaults are: unmodified iced was *slowest* at 460 ms (339 ms repro) because `iced_wgpu` 0.14 defaulted to `HighPerformance` and probed every backend; forcing `WGPU_POWER_PREF=low` and `WGPU_BACKEND=vulkan` dropped it to 175 ms (199 ms repro), ahead of GPUI (253 ms) and Rune (259 ms) [docs/blog/coordinator-notes.md: 460→175ms; docs/upstream/iced-power-preference.md: 339→199ms].

The perf gate against `2caf0fa` exposes the prewarm trade-off. In `compare-isDkA304`, deferring iced's GPU surface attach to save idle RAM caused its lone failure: `click_first_frame_ms` hit 209.8 ms (+112.5 ms vs +75 ms budget) [.cache/perf/out/compare-isDkA304/summary.md: 209.80ms]. Once `nt-core` added in-process `select_egl_vendor()`—cutting renderer init from 171→106 ms in iced and 505→99 ms in Rune [.cache/orchestrate/native-tube/ledger.tsv: 171→106ms, 505→99ms]—iced re-enabled post-Home prewarm and passed all 14 checks at 112.1 ms (+17.6 ms) [.cache/perf/out/compare-F70v7wbg/summary.md: 112.10ms].

### Memory and binary size
Across NOW resource runs (battery, `power` profile), **iced** stays leanest at every stage [docs/media/README.md: 99–267MiB]:
- **Cold Home PSS** (`NT_NO_PREWARM=1`): iced 99 MiB, Rune 131 MiB, GPUI 143 MiB.
- **Warm Home PSS** (default prewarm): iced 153 MiB, Rune 169 MiB, GPUI 188 MiB.
- **Software playback PSS**: iced 211 MiB, Rune 244 MiB, GPUI 255 MiB, versus `ntctl play` at 116 MiB (45–55% core share; 95–139 MiB app residual [docs/media/README.md: 116MiB, 45–55%]).
- **GPU playback PSS**: iced 217 MiB, GPUI 253 MiB, Rune 274 MiB.
- **Tour peak PSS**: iced 267 MiB, GPUI 289 MiB, Rune 337 MiB.

Surprisingly, **Rune flips from second-lightest at idle to heaviest in GPU playback and the tour** (+70 MiB over iced), despite a leaner bare shell (78 MB, 11 threads) than GPUI (96 MB, 32 threads) [docs/blog/coordinator-notes.md: 78 vs 96MB]. Over 60 live opens, Rune plateaued at 453–474 MiB PSS—not a leak, but core's 96 MiB image cache, a 40-page stack, and ~160 MiB of mapped libraries [apps/rune/NOTES.md: 453–474MiB]. Stripped binaries and dependency graphs scale similarly: iced 29.6 MiB (12.5 MB shell, 319 crates), Rune 42.2 MiB (34.1 MB shell, 434 crates), GPUI 52.7 MiB (27.7 MB shell, 640 crates) [docs/media/README.md: 29.6/42.2/52.7MiB; docs/blog/coordinator-notes.md: 319/434/640 crates].

### CPU and GPU work
At idle, all three sleep cleanly: 5.97–6.02M CPU instructions over 10 s (0.60M/s) [docs/media/README.md: 5.97–6.02M], 0.00% idle CPU in final gates [.cache/perf/out/compare-isDkA304/summary.md: 0.00%; .cache/perf/out/compare-F70v7wbg/summary.md: 0.00%], and 2–5 wakeups/s in low-power shells versus 107/s for default iced [docs/blog/coordinator-notes.md: 2/5/3 vs 107/s].

During **playback**, software mode burned 6,525–6,575M instructions over 10 s (~21.8M/frame, 44–45% CPU), 80–82% from `ntctl play` [docs/media/README.md: 6,525–6,575M]. The Wayland GPU subsurface collapsed all three together: Rune 327.54M instructions (1.09M/frame, 9.0–9.5% CPU), iced 352.61M (1.18M/frame, 10.0% CPU), GPUI 352.92M (1.18M/frame, 10% CPU), with nearly identical GPU energy (1.54–1.56 J) and RCS cycles (69.63–75.06 Mcycles) [docs/media/README.md: 327.54–352.92M, 1.54–1.56J].

During **wheel scrolling** (27 ticks), CPU and GPU invert:
- **CPU (`wheel`)**: Rune uses **1,013.41M** instructions (562.40M cycles), iced **1,540.33M** (760.37M cycles), and GPUI **3,020.93M** (1,407.45M cycles)—nearly 3× Rune [docs/media/README.md: 1,013/1,540/3,021M]. Gate `wheel_cpu_percent` agrees: iced 21.95–23.98%, Rune 26.54%, GPUI 45.87% [.cache/perf/out/compare-isDkA304/summary.md: 21.95/26.54/45.87%; .cache/perf/out/compare-F70v7wbg/summary.md: 23.98%].
- **GPU & energy (`wheel`)**: GPUI reports the lowest render work at **35.56 Mcycles** RCS and 0.42 J GPU (19.29 J package), Rune **68.33 Mcycles** and 0.72 J GPU (20.22 J package), while iced spikes to **123.57 Mcycles** RCS plus 14.27 Mcycles VCS, 1.25 J GPU, and 48.12 J package [docs/media/README.md: 35.56/68.33/123.57 Mcycles]. VCS decode activity on iced's Home scroll flags probable system-wide contamination (Section 5), though GPUI's ~2× GPU advantage over clean Rune looks real.

### Stability
Every assessable build scored **100 (3/3 clean, w=0)** on `stability.py`, and NOW builds logged 0 black, 0 stale, and 0 frozen frames across 9 checked switches each [docs/media/README.md: 100, 0/0/0].

The 43-incident catalog (all 43 fixed) tells the real story [.cache/media/out/hiccups.json: 43 incidents]:
- **core (14)**: 1 crash (storyboard overflow), 1 freeze (blocking dub switch), 8 wrong behaviour, 2 perf regressions, 2 review findings [.cache/media/out/hiccups.json: 14].
- **iced (7)**: **0 crashes, 0 freezes**, 4 wrong behaviour, 3 perf regressions (focus loss, prewarm/attach budgets) [.cache/media/out/hiccups.json: 7].
- **Rune (7)**: 1 crash (wrapped `LiveText` release abort), 1 freeze/stall (intermittent GPU switch stall), 3 wrong behaviour, 1 review finding, 1 perf regression [.cache/media/out/hiccups.json: 7].
- **GPUI (6)**: 1 crash (re-entrant `PlayerView` panic), 3 wrong behaviour, 1 review finding, 1 perf regression [.cache/media/out/hiccups.json: 6].
- **orchestration & test tooling (9)**: 5 model usage-limit pauses, 3 test-tooling glitches, 1 private-author commit rewrite [.cache/media/out/hiccups.json: 9].

Frontend totals were nearly identical (6–7), but iced never crashed or stalled, whereas GPUI and Rune both hit framework-level panics.

### Developer and agent experience
First-build agent costs were close: **iced $23.54 (49 min)**, **Rune $27.99 (55 min)**, **GPUI $28.41 (59 min)** [docs/blog/coordinator-notes.md: $23.54/$27.99/$28.41]. Estimated UI effort to full YouTube parity flips the order: **GPUI ~28 h (~$780)**, **Rune ~40 h (~$1,100)**, **iced ~44 h (~$1,220)**, plus ~36 h (~$1,000) shared core work [docs/review/youtube-parity.md: 28/40/44/36h].

For overlays—context menus, storyboards, heatmaps, guide drawers, focus rings—GPUI gives agents `anchored()`, `deferred()`, `.hover()`, blur shadows, `focus_visible`, and `PathBuilder` (heatmap in 20 lines [apps/gpui/NOTES.md: 20 lines]). iced demands `Message` plumbing, hand-positioned `stack`/`Overlay` layers, a binary-searching `Clamp` widget for ellipsis, stretched 1×1 image hacks around `iced_wgpu`'s draw order (quads before images), and manual hover redraws [apps/iced/NOTES.md: 129–141, 270–272]. Rune started concise (~2,500 lines vs iced's ~3,800 [apps/rune/NOTES.md: 2,500; apps/iced/NOTES.md: 3,800]), but re-theming its thin kit and hand-building menus pushed parity effort near iced [docs/review/youtube-parity.md: ~40h]. All three reached zero `#[allow]`/`#[expect]` attributes under crash-proof Clippy lints [.cache/orchestrate/native-tube/ledger.tsv: 0 allows].

### Framework maturity
Seven upstream reports in `docs/upstream/` capture each toolkit's maturity:
- **iced 0.14** needed zero vendored crates or Cargo patches [apps/iced/NOTES.md: 0 deps]; upstream master already fixed `PowerPreference::None` and text ellipsis [docs/upstream/iced-power-preference.md: master]. Remaining warts: no `unfocus()` wrapper in `iced_runtime` [docs/upstream/iced-unfocus-helper.md: 0.14.0] and `row!` dropping zero-width children before positional diffing, silently resetting text-input focus [docs/upstream/iced-focus-sibling-width.md: 0.14.2].
- **GPUI** (`gpui-pre` 0.3.12) is Zed-shaped on Linux. Its Wayland backend drops `wl_pointer.axis_stop`, forcing a vendored ~30-line `gpui-pre-linux` patch for flings [docs/upstream/gpui-axis-stop.md: ~30 lines]. Having no public cursor-hide API forced an inert synthetic keystroke hack [docs/upstream/gpui-hide-cursor.md: 0.3.12], tripping an undocumented panic when `dispatch_keystroke` eagerly redrew a leased view inside `cx.defer_in` [docs/upstream/gpui-reentrant-keystroke.md: entity_map.rs:192]. `paint_surface` is macOS-only [apps/gpui/NOTES.md: 280], and variable fonts broke [docs/blog/coordinator-notes.md: 125].
- **Rune** (`0.0.1` git) is pre-1.0: apps must duplicate `[patch.crates-io]` overrides for `winit` and `wgpu-hal` [apps/rune/NOTES.md: 5–7], leak a `'static` string for `set_app_id` [apps/rune/NOTES.md: 290], call `wl_proxy_get_display` via `libloading` [apps/rune/NOTES.md: 223–226], and avoid a release `assert!` abort when combining `.wrap()` or `.truncate()` with `.live_text()` [docs/upstream/rune-wrapped-livetext.md: flatten.rs:259]. Notably, Rune was the *only* app that rendered readable text out of the box on macOS (GPUI showed none; iced showed dots) [docs/blog/coordinator-notes.md: 126–127].

## 3. Why the numbers look like that: mechanisms

1. **Tree rebuilds vs. retained translation vs. live bindings.** GPUI's `render()` rebuilds element trees on updates; even split into five cached views [apps/gpui/NOTES.md: 5 views], scrolling invalidates `PageView` and burns 3,020.93M CPU instructions [docs/media/README.md: 3,020.93M]. iced's `Scroller` translates laid-out children with `with_translation(0, -offset)`—zero messages or layout per scroll frame between half-viewport bands [apps/iced/NOTES.md: 62–75]. Rune's `poll` updates a `Live<[f32; 2]>` directly on the GPU scene with no view commit, hitting 1,013.41M instructions [apps/rune/NOTES.md: 54–60; docs/media/README.md: 1,013.41M].
2. **Bypassing the UI pipeline for video.** Software playback uploaded ~3.7 MB per 720p frame—a reusable wgpu texture in iced [apps/iced/NOTES.md: 3.7MB], a fresh atlas `RenderImage` in GPUI [apps/gpui/NOTES.md: 278–281], or `Pixels::set` in Rune [apps/rune/NOTES.md: 3.7MB]. Adopting `yt-music-gpui`'s desync Wayland subsurface (`wp_viewporter` + EGL + painting around a hole) removed 30 fps presentation from the UI loop [docs/review/yt-music-gpui-notes.md: 12–34], converging all three to ~10% CPU.
3. **Driver hygiene and prewarm economics.** On hybrid Intel/NVIDIA laptops, driver loading dwarfs Rust micro-optimizations. iced's `HighPerformance` woke the dGPU (+70 MB PSS, +103 wakeups/s) [docs/upstream/iced-power-preference.md: 120→50MB]. Unfiltered EGL attach loaded both Mesa/LLVM and NVIDIA stacks (+38–50 MiB PSS, +90–400 ms init) [apps/iced/NOTES.md: 38MiB; apps/rune/NOTES.md: 50MiB; .cache/orchestrate/native-tube/ledger.tsv: L42]. CUDA probing added ~1.1 s until locked to `vaapi` [.cache/orchestrate/native-tube/ledger.tsv: 1129→79ms]. Prewarming libmpv + GPU surface trades 38–54 MiB idle PSS [docs/media/README.md: 38–54MiB] for ~100 ms faster first playback [.cache/perf/out/compare-F70v7wbg/summary.md: 112.1 vs 209.8ms].
4. **Mutable entity graphs vs. pure message passing.** GPUI's entity model accelerates overlays but relies on runtime borrow leases (`lease_erased`), turning re-entrant redraws into panics [docs/upstream/gpui-reentrant-keystroke.md: 52–53]. iced's Elm loop prevents re-entrancy crashes structurally, at the cost of verbose message plumbing.

## 4. Recommendations: who should pick which

- **Pick GPUI** for **complex, overlay-dense desktop apps** built by AI agents or small teams prioritizing **feature velocity and polish**. Accept ~50 MiB binaries, higher scroll CPU, and small Linux patches; audit every `defer_in`/`dispatch_*` path for re-entrancy.
- **Pick iced** for **runtime frugality, small binaries, zero vendored patches, and crash-free predictability**—especially tools or media players with restrained chrome. Use iced master (or ≥0.15) for `PowerPreference::None` and ellipsis; on 0.14, set `WGPU_POWER_PREF=low` and `WGPU_BACKEND=vulkan` at startup.
- **Pick Rune** only for **R&D, upstream work, or animation-heavy apps** where zero-rebuild `Live` bindings are decisive and you can absorb git pins, `[patch.crates-io]` overrides, and pre-1.0 footguns. Re-evaluate in 12–18 months—its reactive rendering model is the cleanest of the three.
- **Put the hard engineering in a shared headless core.** Isolating networking, fixtures, image decoding, scroll physics, and the Wayland GPU subsurface in `nt-core` [docs/blog/coordinator-notes.md: 9–10] paid off equally across all three frontends (~36 h once [docs/review/youtube-parity.md: 36h]).

## 5. Caveats and open questions

- **Mixed power profiles.** Latency and `perf` counters ran on **AC (`balance_performance`)**, while all 39 resource/PSS runs ran on **battery (`power`)** [docs/media/README.md: 28–30]. Cross-table ratios require re-measurement under one profile.
- **System-wide GPU/RAPL noise.** i915 and RAPL counters measure the whole machine [docs/media/README.md: 129]. iced's `wheel` slice logged 14.27 Mcycles on `VCS` (video decode) and 48.12 J package energy while scrolling Home without video [docs/media/README.md: 14.27 Mcycles], leaving iced's apparent GPU scroll gap unverified until re-run cleanly.
- **Unexplained `ntctl` IPC anomaly.** Standalone `ntctl play` ran *more* instructions (7,065.18M) than all three apps in software playback (6,525–6,575M) while using ~20% *fewer* cycles (3,741.26M vs 4,591–4,695M) and less CPU (36% vs 44–45%) [docs/media/README.md: 7,065.18M vs 3,741.26M]—likely P/E-core scheduling or viewport scaling [docs/media/README.md: 115].
- **Small samples and coarse stability checks.** Metrics are medians of **n = 3** (warm switch spanned 33–88 ms within one build [docs/media/README.md: 33–88ms]), and `stability.py` ran only 3 software-path passes per historical build, missing GPU-path stalls [docs/media/README.md: 95].
- **Linux/Wayland-only data.** Every number comes from one Arrow Lake-P + NVIDIA Hyprland laptop [docs/media/README.md: 129; docs/upstream/iced-power-preference.md: 3]. macOS (where GPUI/iced text broke [docs/blog/coordinator-notes.md: 126]) and Windows remain unbenchmarked.
- **Agent effort ≠ human maintenance, and scope gaps remain.** Parity hours are ±50% AI-agent estimates [docs/review/youtube-parity.md: ±50%]; 1440p/2160p VP9/AV1 playback [docs/blog/coordinator-notes.md: 2160p] and several real-input checks remain open [.cache/orchestrate/native-tube/ledger.tsv: L8,9,38].
